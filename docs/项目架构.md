# 项目架构

B站观众反馈 AI 分析平台面向成长型和成熟型 UP 主。用户输入 BV 号后，系统先展示真实弹幕/评论数据，再流式运行 AI 分析，最终生成可追溯的创作复盘报告。

## 技术栈

- bun workspaces，Node.js 22+
- 后端：NestJS 11、LangChain `createAgent`、`ChatDeepSeek`、Zod、protobufjs
- 前端：React 19、Vite、React Router、Zustand、Tailwind CSS v4、shadcn/ui、Recharts
- 任务传输：NestJS Server-Sent Events；不依赖 LangGraph Server 或 `langgraph.json`

## 页面与数据流

1. `/` 输入 BV 号，`POST /api/analysis/jobs` 创建异步任务。
2. `/workspace/:jobId` 订阅 SSE，显示抓取进度、原始数据图表、弹幕/评论列表、思考内容和工具调用。
3. 后端按时间窗抓取全量弹幕，抓取热门 2000 条与最新 500 条评论并去重。
4. `FeedbackProcessorService` 计算全量确定性统计并构建最多 1200 条评论、3000 条弹幕的分层语义样本。
5. `FeedbackAgentService` 使用 `ChatDeepSeek`（模型与推理强度由 `DEEPSEEK_MODEL` / `DEEPSEEK_REASONING_EFFORT` 环境变量配置）与固定工具写入话题/情感、Top 5、高价值反馈和下一期建议。
6. 服务端校验所有证据 ID，完成后开放 `/report/:jobId`。

## 后端模块

- `BilibiliService`：BV 解析、视频信息、WBI 缓存、弹幕时间窗、热门/最新评论抓取。
- `AnalysisService`：并发上限为 2 的内存任务队列和完整状态机。
- `AnalysisJobStore`：任务 TTL、事件序列、SSE 补发、原始数据分页和报告状态。
- `FeedbackProcessorService`：原始统计、确定性分层抽样、话题次数复算和证据校验。
- `FeedbackAgentService`：LangChain Agent、DeepSeek 推理流和 Zod 工具写入。
- `HttpLoggingInterceptor`：脱敏、截断的请求/响应日志；SSE 只记录连接摘要。

任务默认保留 60 分钟，最多 20 个；超出容量时优先淘汰最旧的已完成或失败任务。服务重启后任务失效，不提供历史记录或账号体系。

## 前端组织

- `src/api/`：所有 HTTP 路径和请求封装。
- `src/types/`：API、任务、事件、原始数据和报告类型。
- `src/stores/analysis-store.ts`：任务事件、推理文本和工具轨迹。
- `src/hooks/use-analysis-stream.ts`：SSE 连接、断线续传；在 `status` 阶段切换和终态时刷新任务视图，使视频信息、覆盖率与原始统计一就绪即可展示，不必等最终 `completed`。
- `src/pages/`：工作台与报告两个页面。
- `src/components/workspace/`、`report/`、`common/`：按业务职责拆分。

## AI 边界

- 评论与弹幕是不可信输入，提示词要求忽略其中的指令。
- AI 报告不得引用未抓取到的评论/弹幕；工具写入时会再次验证 ID。
- 未配置或调用 DeepSeek 失败时，原始数据页仍可用，不生成启发式伪报告。
- 情感比例来自分层语义样本；弹幕密度和话题关键词匹配次数来自已抓取全量数据，界面展示覆盖率。
