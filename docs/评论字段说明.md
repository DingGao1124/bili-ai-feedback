# B站评论数据字段说明

记录后端 `GET https://api.bilibili.com/x/v2/reply/wbi/main`（WBI 签名，游标翻页）抓取评论后，标准化为 `Comment` 的字段语义。

## `Comment` 字段

| 字段 | 类型 | 示例值 | 含义 |
|---|---|---|---|
| `rpid` | string | `"730908554"` | 评论唯一 ID（源 `rpid_str`，字符串防精度丢失） |
| `uname` | string | `"UP主昵称"` | 发布者昵称 |
| `avatar` | string | `"//i0.hdslb.com/...jpg"` | 发布者头像 URL |
| `level` | number | `6` | 发布者当前等级 0-6（源 `level_info.current_level`） |
| `content` | string | `"讲的太好了"` | 评论正文（源 `content.message`，可能含表情/图片标记） |
| `like` | number | `1024` | 点赞数 |
| `replyCount` | number | `36` | 楼中楼回复数（源 `rcount`） |
| `ctime` | number | `1559054600` | 发布时间，Unix 秒 |

## 接口语义（实测）

- **游标翻页**：第一页 `offset=""`；后续页用上一页响应 `cursor.pagination_reply.next_offset` 作为 `offset`。
- `mode=3` 按热度（默认）、`mode=2` 按时间。
- 每页约 20 条；`cursor.is_end` 标记末页，`cursor.all_count` 为评论总数。
- 评论接口**强制要求 WBI 签名**：拿不到 WBI key 时后端直接报错（`BilibiliService.getCommentPage`）。
- 高价值评论识别：本地兜底按 `like + replyCount*3 + level*5` 加权排序（`utils/heuristics.ts` 的 `pickKeyFeedbacks`）。

## 实现位置

- `apps/server/src/services/bilibili.service.ts`：`getCommentPage`（游标翻页）/ `getComments`（分析用，翻页上限 10 页）。
- `apps/web/src/components/result/CommentList.tsx`：分页渲染 + 「加载更多」。
